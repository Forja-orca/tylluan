## 3. MHR Analysis — Why 80% Is Real But Misleading

The 80% MHR (8 out of 10 `long_term_memory` tasks where C1 failed despite having recall)
is a real measurement, but the interpretation requires care:

**What MHR actually measures in this run:** The heuristic evaluator concatenates the
top-3 SilvaDB recall nodes into its response. If those nodes don't contain the task's
exact keywords, the task fails. Since MHR is defined as "C1 failed AND it had recalled
nodes AND family == long_term_memory", all 8 failures count as harm.

**Why this is misleading for product assessment:** The heuristic evaluator doesn't
*reason* about the recalled context — it just echoes the first 3 nodes verbatim. A real
LLM would read the recalled architecture invariant about BGE-M3 and produce a reasoned
answer containing "1024" and "768" and "dimensions". The heuristic can't do that.

**What would make this meaningful:** Running with `--provider http` against a real LLM
(local or remote), where the recalled SilvaDB context is injected into the system prompt
and the model generates a proper response. The 2 tasks that DID pass (mem_04, mem_10)
passed because SilvaDB nodes happened to contain the exact keyword strings.

3. **Sovereign Recall (C1):** Queries SilvaDB via FTS5 BM25 + content LIKE fallback. Top 3 nodes injected into system prompt as "Contexto de memoria soberana (SilvaDB)".
4. **Deterministic Verifier:** `score_task_exact_tokens()` checks response text against task keywords. Threshold: ≥75% keyword match OR (≤2 keywords AND all match).

## 6. Honest Assessment & Next Steps

**What this re-run proves:**
- The harness is clean (no leakage) and produces consistent results across 3 seeds
- SilvaDB recall is working (7218 nodes, FTS5 index populated, real context returned)
- The heuristic evaluator is insufficient to meaningfully assess TSR and MHR
- CD=0 for C1 is correct by construction (C1 never does reconstruction calls)
- OF reduction is model-driven (heuristic assigns lower friction to C1 by design)

**What remains to make TEB-50 a valid product measurement:**
1. **Run against a real LLM** (`--provider http` with a local or remote OpenAI-compatible endpoint). This is the original intent from [TEB_PILOT_SPEC.md](TEB_PILOT_SPEC.md).
2. **Separate the instrument from the result:** OF and CD are currently computed by the harness itself, not observed from actual agent behavior. This is a design limitation, not a bug.
3. **MHR needs real LLM responses** to distinguish "retrieved irrelevant context" from "retrieved context but couldn't reason about it" (the latter is a model limitation, not memory harm).

**Recommendation:** This re-run closes the "re-execute with fixed harness" requirement from T1. The next step (which is a separate task) is to run TEB-50 against a real LLM endpoint to get meaningful TSR/MHR numbers.
