## Alcance

Solo las filas 1-2 de T-DSH-68, en `security/trust.rs` `propagate_untrusted_to_summaries`:

- `let Ok(mut stmt) = conn.prepare(...) else { return 0; }` no dejaba rastro del error.
- `if updated.is_ok() { marked += 1 }` ocultaba el error del `UPDATE`.

## Cambio

- `prepare` ahora es `match`: en `Err(e)` → `tracing::warn!("ASI06 retroactive propagation: failed to prepare summary query: {e}")` y `return 0`.
- `UPDATE` ahora es `match`: `Ok(_)` → `marked += 1`; `Err(e)` → `tracing::warn!("ASI06 retroactive propagation: failed to mark summary '{id}': {e}")` y no cuenta.
- Firma y valor de retorno no cambian; sigue siendo no fatal.

## Test

`propagate_untrusted_does_not_count_write_failure` (`multi_thread`, porque `SilvaDB::in_memory` usa `block_in_place`):

1. Crea un nodo fuente `untrusted_content=true` y un `agent_summary` que contiene su preview (con `NodeWriteOptions::drift_allowed(true)`).
2. Pone la conexión en `PRAGMA query_only=ON`: SELECT funciona, UPDATE falla con "attempt to write a readonly database".
3. `propagate_untrusted_to_summaries` devuelve **0** y no hace panic.
4. El summary sigue sin `untrusted_content`; se restaura `query_only=OFF`.
