## Cambio

Antes:

```rust
if counts.get(guild).and_then(|v| v.as_object()).is_none() {
    counts[guild] = json!({"successes": 0, "total": 0});
}
let stats = counts.get_mut(guild)
    .and_then(|v| v.as_object_mut())
    .expect("guild stats entry initialized immediately above");
```

Ahora (`upsert_activity`, líneas 87-114):

- Si `competencies` no es un objeto JSON (DB vieja/corrupta, p. ej. `[]`), se normaliza a `{}` con `tracing::warn!` en vez de dejar que el `counts[guild] = ...` no inserte.
- Se usa `entry(guild).or_insert_with(...)`; si la entrada existe pero no es objeto, se reemplaza por `{"successes":0,"total":0}`.
- `as_object_mut()` se maneja con `let Some(...) else { return Ok(()) }`; no hay `expect` ni `unwrap` en la ruta.
- Si por una invariante rota no se puede obtener el objeto, se devuelve `Ok(())` (se pierde esa actividad, pero no se tumba el kernel).

El resto de la función (actualización de `total_calls`, `competencies`, `last_intent` y `agent_domain_scores`) no cambia.

## Test

`test_upsert_activity_recovers_from_non_object_competencies` (módulo de tests de `agent_profile.rs`). Fuerza dos estados persistidos que antes podían caer en el `expect`:

1. `competencies = '[]'` (array, no objeto) → `upsert_activity` no hace panic; el JSON crudo queda con `bash.total=1` y `bash.successes=1`.
2. `competencies = '{"bash":"not-an-object"}'` → se reemplaza la entrada de la guild; `bash.total=1`, `bash.successes=0`.

El test consulta el JSON crudo de SQLite (no `get_profile`, que devuelve competencias ya convertidas a porcentaje) y además comprueba que `get_profile` no falla.
