# D-38 — Puerto ocupado: reintento acotado y fallo claro (nunca puerto aleatorio)

- **Agente:** deep
- **Fecha:** 2026-10-24
- **Base:** `E:\tylluan-wt-deep` en `--detach origin/main` (`fa39592`) **con D-39b aplicado**
- **Estado:** implementado, tests y clippy verdes; **no verificado en vivo** (no arranco kernels)
- **Orden de aplicación:** este parche es un **delta sobre D-39b** (ambos tocan
  `start_http_server` en `transport/http/mod.rs`). Aplicar D-39b primero.

## Qué cambia

1. `[nexus].port_retry_secs` (nuevo, default **10**, `0` = fallar de inmediato).
   Documentado en `tylluan.example.toml`. No se toca `tylluan.toml`.
2. **Se elimina el fallback silencioso**: ya no se escanea `port+1..=port+100` ni
   se bindea `:0`. Si el puerto configurado está ocupado, el kernel reintenta ese
   mismo puerto cada 500 ms hasta agotar `port_retry_secs` y entonces **falla con
   error claro**:
   `puerto host:port ocupado tras N intentos (Xs): <error real>. No arranco en otro
   puerto (D-38). Cierra el proceso que lo ocupa o cambia [nexus].port / sube
   [nexus].port_retry_secs.`
3. Antes de bindear, si `data/active_port.json` apunta a un puerto del rango que
   este kernel pudo haber bindeado (`port..=port+100`, `!= 0`), se envía el
   shutdown al kernel anterior y se espera su respuesta (timeout 3 s), con log del
   resultado. El bloque de shutdown que antes corría **después** del bind se mueve
   aquí; ya no se puede dar el caso "nuevo kernel en puerto X, viejo en Y" porque
   el nuevo siempre usa el configurado.
4. Cada intento fallido loguea el error real (`warn!`), en vez del antiguo
   `Err(_) => continue` que descartaba la causa.

## Por qué el "No candidate ports" de 27 ms

Lectura del código anterior: el bucle hacía 100 `bind()` consecutivos; un
`AddrInUse` se resuelve en microsegundos, así que 27 ms es coherente con 100
fallos inmediatos. El bucle descartaba cada error (`Err(_) => continue`) y, al no
encontrar ninguno, bindeaba `:0` (puerto aleatorio) con un `info!`. No reproducido
en vivo; con D-38 esa ruta desaparece.

## No verificado

- Reinicio real con un kernel anterior vivo: no arranco kernels. El orden
  shutdown→retry→bind está en código, pero no medí cuánto tarda el shutdown real
  ni el caso "el viejo no responde en 3 s".
- El fallo final con un proceso no-Tylluan ocupando el puerto solo está cubierto
  por test unitario (squatter), no por un arranque real.
- Cómo verificarlo (TL): ocupar 47004 con otro proceso, arrancar el kernel con
  `port_retry_secs = 2` y comprobar que (a) reintenta ~4 veces con el error real,
  (b) termina con el mensaje claro y (c) no queda escuchando en otro puerto.

## Impact

- **Superficie:** arranque HTTP (`transport/http/mod.rs`), `[nexus]` y main.rs.
  Sin cambios en guilds, federación, ACL ni datos.
- **Comportamiento:** cambio deliberado de "arranca en otro puerto en silencio" a
  "falla claro". Un operador con el puerto ocupado por un proceso ajeno ya no
  obtiene un kernel a la escucha en un puerto desconocido. El hot-swap sigue
  funcionando: se pide shutdown al anterior y se reintenta el puerto configurado.
- **Compatibilidad:** campo de config nuevo con default (10 s); configs viejas
  siguen cargando. `tylluan.toml` de producción no se toca.
- **No depredación:** solo workspace `E:\tylluan-wt-deep`; sin tocar el checkout
  compartido; sin procesos lanzados.
