## Bug

Con el puerto ocupado, D-38 hace que `start_http_server_with_download` devuelva un error claro. Pero ese error se quedaba dentro de la tarea HTTP:

```rust
tokio::spawn(async move {
    if let Err(e) = start_http_server... {
        error!("...: {e}");   // y la tarea muere
    }
});
```

`main` seguía vivo en la espera de stdio (o de Ctrl+C), sin puerto. Un lanzador que espera la salida del proceso se cuelga indefinidamente; DSH lo midió >90 s en `IMPL_T-DSH-58`.

---

## Arreglo

- `main.rs` linea 1413: canal `watch::channel::<Option<String>>(None)` entre la tarea HTTP y `main`.
- La tarea HTTP publica `None` si termina bien y `Some(error)` si el arranque/servidor falla (linea 1429/1433).
- `transport::http::wait_for_shutdown()` (`transport/http/mod.rs` linea 309) sustituye los dos `tokio::select!` de `main`:
  - espera stdio, Ctrl+C, cancelación **o** un error HTTP;
  - si el HTTP falla, devuelve el error (no se pierde aunque stdio/Ctrl+C estén listos, porque el `watch` conserva el último valor);
  - la tarea HTTP desaparecida sin publicar resultado (panic) también cuenta como fallo.
- `main` linea 2184 consume el resultado, loguea `HTTP transport failed; shutting down: ...` y cancela el token para que el shutdown limpie guilds/servicios/PID.
- Al final del shutdown (linea 2237) `std::process::exit(1)` si hubo fallo HTTP. Una parada normal (stdio/Ctrl+C/cancelación) sigue saliendo con 0.
- **No se tocó D-38**: ni los reintentos ni `port_retry_secs`. Tampoco el valor por defecto del puerto.

## Impact

- **Superficie:** arranque/parada (`main.rs`) y `transport/http/mod.rs` (helper + tests). Sin guilds, ACL, datos ni configuración.
- **Comportamiento:** si el HTTP no puede arrancar, el proceso termina con código 1 después de cerrar limpio lo abierto. Si el HTTP está desactivado o la parada es normal, el comportamiento es el de antes.
- **Seguridad/operación:** un lanzador ya no se queda esperando un proceso zombi sin puerto; el fallo de D-38 deja de ser silencioso a nivel de proceso.
- **No depredación:** D-46 estaba asignado a Deep; no se tocó el checkout compartido ni `tylluan.toml`.
