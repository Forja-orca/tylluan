## Decisión 1 — concurrencia: el semáforo ya existía (D-14/C2)

No lo dupliqué. `crates/tylluan-kernel/src/security/coherence_gate.rs` ya tenía:

- `JUDGE_MAX_CONCURRENCY = 1` (`:152`).
- `JUDGE_QUEUE_WAIT = 60 s` (`:158`).
- `judge_semaphore()` (`:162`) y `acquire_judge_permit()` (`:177`): si no hay ranura en 60 s, el juicio se salta y se cuenta como `busy_skip`.
- Tests existentes: `one_slot_matches_the_server_started_without_parallel` y `bounded_wait_skips_and_counts_instead_of_queueing_forever`.

**Por qué no añadí un knob `judge_max_concurrency`:** `llama_backend` arranca `llama-server` SIN `--parallel`, o sea una sola ranura real. Poner 2+ no acelera: encola dentro del modelo y cada juicio espera la suma de los anteriores, además de multiplicar el coste de memoria. El semáforo de 1 es fiel al recurso, no una limitación arbitraria. Si algún día se arranca `llama-server --parallel`, ese knob debe ir junto con ese cambio, no antes.

**Consecuencia:** D-36 añade la pieza que faltaba (dedupe). La concurrencia queda como estaba y con tests; el informe lo deja explícito para que no se cuente como trabajo nuevo.

## Decisión 2 — dedupe por contenido (lo nuevo)

En `coherence_gate.rs`, en el único embudo que usan la capa 2 (write gate ASI06) y la capa 4 (`call_reasoning_backend_with_grammar`):

- Clave = SHA-256 de `gramática + NUL + prompt`. Incluye la gramática para que el veredicto de la capa 2 y el de la capa 4 no se mezclen.
- Se cachea **solo un veredicto `Ok`**. Un error/timeout/HTTP no se cachea: el siguiente intento vuelve al modelo.
- Ventana por defecto **60 s**; `0` desactiva el dedupe. Tope por defecto **256 entradas**; se evicta la más antigua. Límites duros: 3600 s y 4096 entradas.
- La caché guarda **hash + veredicto**, nunca prompt ni contenido.
- El dedupe se consulta **antes** de pedir la ranura (un repetido no consume generación) y **otra vez después** de adquirirla. Con concurrencia 1, dos llamadas idénticas simultáneas no generan dos veces: la segunda espera el permiso, lo recibe cuando la primera ya guardó, y sale de caché.
- Config nueva en `[security]`:
  - `judge_dedup_window_secs` (default 60).
  - `judge_dedup_max_entries` (default 256).
- Se leen con `TylluanConfig::load_cached()` en cada juicio, igual que `configured_judge_model()`, así que un reload de config se respeta sin reiniciar.

### Qué significa "sin cambiar el comportamiento si el juez está apagado"

- Si la capa 4 está apagada (`coherence_gate_hybrid_enabled=false`), no hay llamadas desde recall; no hay caché que consultar.
- Si el backend no está disponible, todas las llamadas devuelven error y **no se cachea nada**: el comportamiento sigue siendo "falla y se cuenta", no "falla y se finge veredicto".
- Si el juez está activo, el veredicto es el mismo (temperatura 0.0 + gramática); solo se evita repetir la misma generación dentro de la ventana.
