**Estado:** implementado y verificado en worktree. **NO verificado con el endpoint en vivo. NO comiteado** (lo comitea el TL).

---

## Problema

`audit_log_handler` (`api_v1/mod.rs`) abría `./data/audit.db` hardcodeado, mientras el writer (`log_audit_entry`) y los demás lectores resuelven `audit_db_path()` (que respeta `TYLLUAN_AUDIT_DB`). Con la variable o un CWD distinto, el endpoint leía otra DB. Además el `CREATE TABLE IF NOT EXISTS` se descartaba con `let _ =`.

## Cambio

- `audit_read_db_path()` (nuevo helper) → `crate::transport::server::handler_do::audit_db_path()`.
- El handler usa `let db_path = audit_read_db_path();` y `open_db(&db_path)`.
- El `CREATE TABLE` ahora:
  ```rust
  if let Err(e) = conn.execute_batch(...) {
      tracing::warn!("audit endpoint: failed to ensure guild_audit_log: {e}");
  }
  ```
  Sigue siendo no fatal, pero ya no invisible.
- No se toca la lógica de verificación de cadena ni otros endpoints.

## Test

- `handler_do/audit.rs`: el test seam `audit_store_seam_write_and_read_land_on_same_file` pasa de un `AtomicBool` local a un `AUDIT_ENV_TEST_LOCK` compartido (test-only), porque ahora hay dos tests que tocan `TYLLUAN_AUDIT_DB`.
- Nuevo test `d53_audit_read_path_tests::audit_read_path_uses_env_seam`:
  1. Toma el lock compartido.
  2. Apunta `TYLLUAN_AUDIT_DB` a un tempdir.
  3. `audit_read_db_path()` devuelve exactamente esa ruta.
  4. Sin env, vuelve a `./data/audit.db`.

- **Superficie:** `GET /api/v1/audit` (`api_v1/mod.rs`) y el seam de tests de `handler_do/audit.rs`. Sin cambios de esquema, writer ni verificación de cadena.
- **Comportamiento:** el lector usa la misma DB que el writer, con `TYLLUAN_AUDIT_DB` y CWD distinto incluidos. Un fallo de `CREATE TABLE` deja un `warn!` en vez de desaparecer.
- **Riesgo:** bajo; el path por defecto sigue siendo `./data/audit.db`. El único cambio extra es el lock de tests para evitar carreras de env.
