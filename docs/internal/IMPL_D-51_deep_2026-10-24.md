## Cambio 1 — orden de PRAGMAs

Antes (`config.rs`, línea 1530):

```
PRAGMA journal_mode=WAL;
PRAGMA busy_timeout=5000;
...
```

Ahora:

```
PRAGMA busy_timeout=5000;
PRAGMA journal_mode=WAL;
PRAGMA synchronous=NORMAL;
PRAGMA cache_size=-65536;
PRAGMA mmap_size=268435456;
```

Sobre un fichero nuevo, el cambio a WAL puede devolver "database is locked" si otra conexión está abriendo la BD. Con `busy_timeout` armado antes, SQLite espera hasta 5 s en vez de fallar de inmediato. Los valores son idénticos; solo cambia el orden.

## Cambio 2 — auditoría de denegación visible

Antes (`permissions.rs`, línea 213):

```rust
let _ = log_audit_entry(...);
```

Ahora:

```rust
if let Err(e) = log_audit_entry(...) {
    tracing::warn!("federation permissions: failed to audit denial for peer '{peer}': {e}");
}
```

La denegación ya se aplicó; un fallo de auditoría no cambia la decisión, pero deja de ser invisible. Es exactamente el caso H1 de T-DSH-66: si la fila no se escribe, antes t15 veía 0 y nadie sabía por qué.
